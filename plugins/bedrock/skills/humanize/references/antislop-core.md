# Anti-slop, any language

Patterns that make text read as generated. One instance can pass; the tell is density.
Fix them while writing, then let lint catch what slipped through. Phrases lint rejects
outright are in `stoplist.txt`.

## Rhythm

- Vary length. Generated text runs at a metronome pace; people do not.
- No rule of three. "fast, clean and reliable" everywhere is a tell. Use one, two or four.
- No announced structure: intro, three tidy points, wrap-up. Start where the point is.
- No one-word sentences for drama. "Done. Shipped. Live."

## False weight

- Not every update is important. A deploy note is a deploy note.
- No moral at the end, no "the bigger picture". Stop when the information stops.
- No fake reveal: "here's the thing", "but the real story is".
- No "obviously", "clearly", "simply" to assert what was not shown.

## The contrast frame

"Not X, but Y", "it's not X, it's Y", "not because X, but because Y", "the question is
not X, it is Y". The single most recognisable tell. Say the positive thing directly.

## Filler moves

Cut phrases that announce a move instead of making it ("worth noting", "when it comes
to", "let's dive in", "важно отметить", "давайте разберемся"). Write to a peer.

## Specifics

- Name the source or drop the claim. No "experts say".
- Never invent a number, date, quote or example to sound grounded.

## Punctuation and formatting

- Dashes follow the profile; in the default voice, none.
- At most one exclamation mark, and only if the register uses them.
- No trailing "..." for suspense.
- No bold lead-in on every bullet. Lists only when the content is a real list.
- No emoji unless the register uses them.

## Final check

Read it as the recipient. Would this specific person send exactly this? Any line that
sounds like an assistant gets rewritten. Plain and specific beats smooth and general.
